AI-ready semantic models: prepare a model so Copilot answers correctly

Take a working Direct Lake sales model and make it safe for Copilot: clean names and descriptions, a trimmed AI data schema, AI instructions that settle what 'margin' means, one verified answer and the Approved for Copilot setting. With six test questions and the answers Copilot should give.

11 Oct 2026 Fabric as of October 2026 Checked against Microsoft Learn Level 2 Ankur Napa AIPower BIDirect Lake

Short answer

Copilot in Power BI writes DAX against your model's metadata. If two measures could both be "margin", it will pick one. You will not know which until someone quotes it. Preparing a model for AI means removing that choice: business names, descriptions, hidden plumbing columns, then Prep data for AI with an AI data schema, AI instructions and verified answers. Finish by marking the model Approved for Copilot. Q&A must be on for the model or the Prep data for AI tabs stay disabled. For a Direct Lake model, author all of this in the Power BI service, because Desktop supports the feature only for Import, DirectQuery and local composite models. The whole feature set is in preview and the answers stay nondeterministic. Test with fixed questions and known answers.

What you will build

The sm_sales_kpis model from Your first Direct Lake model answers dashboards well. Ask Copilot "what is our margin?" and it has two honest options: Gross margin % (35.8 per cent) and Average order margin % (37.6 per cent). A model that is fine for a careful report author is a coin toss for a chat window.

By the end, the model will have:

  • Business names and descriptions on every field Copilot can see.
  • An AI data schema that leaves out keys, raw amounts and sort helpers.
  • AI instructions that define sales, margin, quarters and stores.
  • One verified answer for "margin by category".
  • The Approved for Copilot flag.

Before you start

  • The sm_sales_kpis model and the sample data direct-lake-model-sales-kpis.csv: 66 orders, July to September 2026, rupees.
  • Copilot enabled for your tenant and the workspace on a capacity where Copilot is allowed.
  • Write permission on the model.
  • A region check. Learn lists the standalone Copilot experience as not yet available in Spain Central, Qatar, India-West and Mexico. The report Copilot pane is a separate experience. If your capacity sits in India-West, test in the report pane.

Step 1: fix the model before touching the AI tooling

Copilot reads names, descriptions and visibility. Fix those first.

  1. Open the model from the workspace (... > Open semantic model) and switch to Editing.
  2. Hide fields nobody should ask about: fact_sales[product_key], dim_product[product_key], dim_date[month_no], fact_sales[net_amount] and fact_sales[cost_amount]. The measures already cover the amounts.
  3. Rename the visible columns that still read like code. fact_sales[store_id] becomes Store, dim_product[product] becomes Product, dim_product[category] becomes Category, dim_date[month] becomes Month. Renaming in the model does not touch the Delta column underneath.
  4. Select each measure and fill in Description in the Properties pane:
MeasureDescription
Net salesOrder value after discount, in Indian rupees, excluding tax.
Gross margin %Net sales minus product cost, divided by net sales, over the whole selection. The standard margin figure.
Average order margin %Simple average of each order's margin. Use only when asked for a per-order average.
  1. Check for duplicate field names across tables. Two columns called date in different tables is enough to send a question to the wrong one.

Step 2: turn on Q&A

  1. In the workspace, open ... on sm_sales_kpis > Settings.
  2. Expand Q&A and switch it on. Select Apply.

The Prep data for AI dialog also offers to switch Q&A on when it finds it off.

Step 3: simplify the data schema

  1. Open the model page in the service and select Prep data for AI on the ribbon.
  2. Go to Simplify data schema.
  3. Leave ticked: the three measures, Store, Product, Category, Month, dim_date[date], dim_date[year], order_id and quantity.
  4. Untick everything else, including unit_price and discount. A question about discounts is a real question, but it deserves its own measure first, not a raw column Copilot will sum.
  5. Select Apply.

Step 4: write AI instructions

Go to the Add AI instructions tab and paste:

Business context
- Harbour Goods is a retailer with six stores in India. All money is in Indian rupees (INR).
- Data covers orders from 1 July 2026 to 30 September 2026, one row per order.

Metrics
- "Sales", "revenue" or "turnover" without another qualifier means [Net sales].
- "Margin" or "gross margin" means [Gross margin %]. Do not use [Average order margin %]
  unless the user asks for an average per order.
- Report margins to one decimal place as a percentage.

Dates
- Quarters are calendar quarters. Q3 2026 is July to September 2026.
- Use 'dim_date'[date] for all date filtering.

Stores
- Stores are identified by codes such as ST-014. If the user names a city, ask which store
  they mean rather than guessing.

Ambiguity
- If "performance" could mean sales or margin, ask which one the user wants.

Select Apply. Instructions are limited to 10,000 characters and end users cannot see them. Short and grouped beats long and clever; contradictions between instructions are a common reason Copilot ignores one of them.

Step 5: add one verified answer

A verified answer ties trigger phrases to a visual you built and checked. For Direct Lake models these are authored in the service only.

  1. Create a report on the model with a clustered bar chart: Category on the Y-axis, Gross margin % on the X-axis, sorted ascending. Add Store to the report-level filters and leave it set to all.
  2. In edit mode, select the visual, open ... and choose Set up a verified answer.
  3. Add trigger phrases: margin by category, which category has the lowest margin, gross margin per category.
  4. Under filters, make Store available to users. It qualifies only because it exists on the report and has no value applied.
  5. Select Apply and save the report.

Limits worth knowing: 250 verified answers per model, 15 trigger phrases each, 10 filter permutations each. Relative date filters such as "last three months" are not supported as verified answer filters.

Step 6: mark it Approved for Copilot

  1. Open the model Settings again.
  2. Expand Approved for Copilot, tick the box and select Apply.

This removes the friction treatment the standalone Copilot applies to unapproved models. Changes usually show within an hour and can take up to 24 hours on a model with many reports.

Check it worked

Open the Copilot pane on the report and ask each question three times in a fresh chat. All expected answers were computed from the 66-row sample.

QuestionExpected answer
What were net sales in August 2026?162,931.25
What is our margin?35.8% (Gross margin %, not 37.6%)
What was gross margin in Q3 2026?35.8%
Which category has the lowest margin?Electronics, 29.1% (verified answer badge)
Which store sold the most?ST-014, 106,845.15
How did Pune do?A clarifying question about the store

For every answer, open How Copilot arrived at this and check the measure it used. A right number from the wrong measure is a failure that will surface next quarter. If a change does not show, close and reopen the Copilot pane; changes can take a few minutes to apply.

Where this breaks

  • Preview. Prep data for AI is in preview. Labels move and behaviour changes. Keep the test table and rerun it after every model change.
  • Hidden fields break verified answers. A verified answer that uses a hidden field, or a filter field left out of the AI data schema, is not returned reliably.
  • Deployment needs a refresh. AI instructions and schema live in the model's linguistic schema. After a Git sync or deployment pipeline move, a Direct Lake model must be refreshed in the service for the changes to apply. Learn qualifies that with "only once a day" for Direct Lake models, so expect a delay rather than an instant change.
  • Field parameters. Q&A and AI visuals do not support field parameters. Pages built on field parameters give Copilot the visual's current state only.
  • RLS still applies, unseen. Copilot answers within the user's roles. Test as role cannot validate Copilot, so test restricted users by signing in as them.
  • Instructions are advice. The model interprets them. They do not disable features or guarantee a measure choice. Descriptions and a trimmed schema do more of the work.

On the brewhouse floor

A winery's sales model has the same trap with a different word. Ask Copilot for "volume" and it can answer in bottles, nine-litre cases or litres, all of which sit in the model. A winery shipping 12,000 cases a quarter is moving 108,000 litres or 144,000 bottles, three true numbers that look nothing alike. One instruction line ("volume means nine-litre cases unless the user says otherwise") and a description on each measure settle it before the export manager quotes litres to a distributor who buys in cases.
