Calculation groups and field parameters: fewer measures, more answers

Add one calculation group that turns any measure into quarter to date, previous month or month on month, then a field parameter that lets report readers swap the measure and the breakdown. Built on a Direct Lake sales model with every expected number worked out.

11 Oct 2026 Fabric as of October 2026 Checked against Microsoft Learn Level 2 Ankur Napa Power BIDirect Lake

Short answer

A calculation group holds calculation items, each a small DAX expression wrapped around SELECTEDMEASURE(). Put the group on a visual and every explicit measure in the model gets quarter to date, previous month and month on month without you writing those measures twelve times. A field parameter is different: it changes which field a visual shows, not how it is calculated. Use the calculation group when the same pattern repeats across many measures. Use the field parameter when readers want to pick the measure or the breakdown themselves. Both are allowed in Direct Lake models because they create calculated tables that do not read Direct Lake columns.

What you will build

On the sm_sales_kpis model from Your first Direct Lake model, three measures already exist: Net sales, Gross margin % and Average order margin %. Without a calculation group, adding quarter to date, previous month and month on month means nine more measures. Add one more base measure next year and you are writing three more again. That is how a model ends up with 140 measures and a folder called old do not use.

You will add:

  • A calculation group Time calc with four items: Current, QTD, PM and MoM.
  • A field parameter Measure picker holding the three measures.
  • A field parameter Breakdown holding product category and store.
  • A one-page report where a reader picks the measure, the breakdown and the time calculation from three slicers.

Before you start

  • The lh_sales_gold lakehouse and sm_sales_kpis Direct Lake model from the earlier walkthrough, loaded from direct-lake-model-sales-kpis.csv. 66 orders, July to September 2026, rupees.
  • dim_date marked as the date table, with one row per day and no gaps. Time intelligence functions such as DATESQTD and DATEADD need a contiguous date column.
  • Write permission on the model. For the field parameter you also need Power BI Desktop.

Step 1: create the calculation group in the browser

  1. In the workspace, open the ... menu on sm_sales_kpis and select Open semantic model. Switch to Editing in the top right corner.
  2. In model view, select Calculation group on the ribbon.
  3. If Discourage implicit measures is off, a dialog asks to turn it on. Select Yes. Calculation items only apply to explicit measures, so the model stops offering the summation drop-down on raw columns from now on.
  4. A group appears with one item already set to SELECTEDMEASURE(). In the Data pane, double-click the group and rename it Time calc. Rename its column to Time calculation. Rename the first item to Current.
  5. Right-click Calculation items and select New calculation item three times. Name them and paste the expressions below.

QTD:

CALCULATE ( SELECTEDMEASURE (), DATESQTD ( dim_date[date] ) )

PM (previous month):

CALCULATE ( SELECTEDMEASURE (), DATEADD ( dim_date[date], -1, MONTH ) )

MoM:

VAR CurrentValue = SELECTEDMEASURE ()
VAR PriorValue =
    CALCULATE ( SELECTEDMEASURE (), 'Time calc'[Time calculation] = "PM" )
RETURN
    IF (
        ISBLANK ( PriorValue ),
        BLANK (),
        IF (
            ISSELECTEDMEASURE ( [Gross margin %], [Average order margin %] ),
            CurrentValue - PriorValue,
            DIVIDE ( CurrentValue - PriorValue, PriorValue )
        )
    )
  1. Select the MoM item and in the Properties pane turn on Dynamic format string. Set it to:
"+0.0%;-0.0%;0.0%"

The ISSELECTEDMEASURE branch is the part most templates skip. Month on month for Net sales is a relative change: September down 9.5 per cent. Month on month for a margin is a difference in points: September up 0.7 points. A relative change of a percentage (2.1 per cent better than 35.9 per cent) is technically correct and useless in a meeting. Write the rule once here and every report inherits it.

The blank guard matters too. dim_date starts on 1 July, so July has no previous month. Without the guard, July MoM for a margin measure returns the full margin as if June had been zero.

Step 2: check the group with a DAX query

From the model's ... menu select Write DAX queries and run:

EVALUATE
SUMMARIZECOLUMNS (
    dim_date[month],
    'Time calc'[Time calculation],
    "Net sales", [Net sales],
    "Gross margin %", [Gross margin %]
)
ORDER BY dim_date[month], 'Time calc'[Time calculation]

You should get twelve rows, three months times four items. If an item returns an error, check that its expression refers to dim_date[date] and not a column name copied from a sample.

Step 3: add the field parameters in Desktop

Field parameters are created from Power BI Desktop. Learn documents the path Modeling > New parameter > Fields. With a Direct Lake model you live edit it: in the workspace, open the model and select Edit in Desktop (some tenants label it Open in Power BI Desktop).

  1. Select Modeling > New parameter > Fields.
  2. Name it Measure picker. Add Net sales, Gross margin % and Average order margin %. Leave Add slicer to this page ticked if offered. Select Create.
  3. Repeat for Breakdown, adding dim_product[category] and fact_sales[store_id].

The parameter is a calculated table. Its DAX looks like this. You can edit it directly to rename or reorder entries:

Breakdown = {
    ( "Category", NAMEOF ( dim_product[category] ), 0 ),
    ( "Store", NAMEOF ( fact_sales[store_id] ), 1 )
}

Learn does not say whether New parameter is available while live editing a Direct Lake model. If the button is greyed out, the documented fallback is a report that connects to the model with DirectQuery for Power BI semantic models and adds a local model, where field parameters can be created. That puts the parameter in the report file rather than the shared model.

Step 4: build the page

Create a report on the model (from the workspace, ... on sm_sales_kpis > Create report) and add:

  1. A slicer on Time calc[Time calculation], single select.
  2. A slicer on Measure picker, single select.
  3. A slicer on Breakdown, single select.
  4. A clustered column chart with Breakdown on the X-axis and Measure picker on the Y-axis.
  5. A matrix with dim_date[month] on rows, Time calc[Time calculation] on columns and Net sales in values.

Save it as rpt_sales_explorer.

Where this breaks

  • Every measure becomes variant. As soon as a calculation group exists, reports treat all measures as the variant data type. Measures that feed dynamic format strings can error. Learn's fix is to wrap them in FORMAT ( [measure], "" ).
  • Text measures and calculation items. A dynamic title measure under the MoM item hits "Cannot convert value of type Text to type Numeric". Guard numeric maths with ISNUMERIC ( SELECTEDMEASURE () ) if you keep text measures in the same model.
  • Two groups, wrong order. Add a currency group later and precedence decides which wraps which. The higher precedence group is applied outside the lower one. Only its dynamic format string wins. Get it wrong and QTD in euros converts a quarter of rupees at one month's rate.
  • Odd totals. At the matrix total, PM shifts the whole quarter back one month and returns July plus August. That is correct DAX and a confusing number. Hide totals on time calculation columns.
  • Copilot and field parameters. Q&A and AI visuals do not support field parameters. Copilot answers from the current state of the visual. Keep a plain page of the main measures for anyone using Copilot on this model.
  • Implicit measures stop working. Existing visuals that summed a raw column keep working, but nobody can drag a new one. Expect one message from the person who builds reports by dragging columns.

On the brewhouse floor

A brewery has the same measure sprawl with different names: packaged hectolitres, brewhouse yield, beer loss and cost per hectolitre, each wanted this month, quarter to date and against last month. One calculation group gives all four the same three views. The MoM rule earns its keep here. Beer loss going from 4.0 to 4.6 per cent is a 0.6 point rise, which on a 1,000 hectolitre month is six hectolitres of beer down the drain. Call it a 15 per cent rise and the production manager hears a disaster that is really a filter change on the centrifuge.
