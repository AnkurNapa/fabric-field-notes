Data engineering basics, lesson 5 of 8

Your first pipeline: copy data into a lakehouse

Lesson 5 of Data engineering basics. Build a Fabric pipeline with one Copy activity that lands the Harbour Goods orders file as a raw bronze table, run it and prove every row arrived.

11 Oct 2026 Fabric as of October 2026 Checked against Microsoft Learn Ankur Napa Lakehouse

Short answer

A pipeline in Fabric is a list of steps, called activities, that run in order. The most common activity is Copy data, which reads from a source and writes to a destination without you writing code. In this lesson one Copy activity reads the orders CSV from the lakehouse Files area and writes it to a Delta table called bronze_orders. You then count the rows to prove nothing was lost. Lessons 7 and 8 add more activities to this same pipeline.

Why it matters for your career

Copying data reliably from A to B is the first thing every data engineering job asks of you. A pipeline you can run, rerun and explain is a better portfolio piece than a clever notebook nobody can schedule.

The idea

In lesson 2 you used Load to tables, a one-off click. A pipeline does the same kind of work but is saved, repeatable and can be scheduled. That makes it the right tool for a file that arrives every day.

The table is called bronze because it holds the data exactly as it arrived, mistakes included. Lesson 8 explains the bronze, silver and gold naming fully.

In real life the source would be the till system's database or a folder the supplier drops files into. Fabric has connectors for both. Reading from the lakehouse keeps this exercise free of passwords and firewalls.

Try it in Fabric

You need the landing folder and CSV from lesson 2. If you skipped it, download harbour-goods-orders.csv and upload it to Files/landing in lh_harbour.

  1. In the harbour-dev workspace select + New item, search for Pipeline and select it. Name it pl_orders_daily and select Create.
  2. On the empty canvas select Copy data to open the copy assistant. You can also use the Activities tab > Copy data dropdown > Use copy assistant.
  3. Choose data source. Pick your lakehouse lh_harbour from the OneLake catalog list. If it is not shown, search for it by name.
  4. Connect to data source. Select Files, browse to landing/harbour-goods-orders.csv and set the file format to DelimitedText. Make sure the option that treats the first row as a header is ticked. The preview should show seven columns with order_id first. Select Next.
  5. Choose data destination. Pick lh_harbour again.
  6. Connect to data destination. Choose Tables, create a new table, set the schema to dbo and the name to bronze_orders. In the column mapping, leave every type as String. Set the table action to Overwrite. The label may read Table action or appear under Load settings. Select Next.
  7. Review and create. Check the summary and select OK or Save. A Copy activity appears on the canvas.
  8. On the Home tab select Save, then Run. Watch the Output tab under the canvas. The status moves from In progress to Succeeded, usually within a minute or two for a file this small.

Keeping every column as text in bronze is deliberate. The file contains the impossible date 2026-09-31. If you set order_date to a date type in the mapping, the copy fails on that row. Bronze should accept whatever arrives; checking happens next.

Check it worked

Open lh_harbour, switch to the SQL analytics endpoint, select New SQL query and run:

SELECT
    COUNT(*)                          AS order_lines,
    COUNT(DISTINCT order_id)          AS distinct_orders,
    SUM(TRY_CAST(quantity AS int))    AS total_units
FROM dbo.bronze_orders;

Expected: 60 order lines, 59 distinct orders and 104 units. If bronze_orders is missing from the endpoint, select Refresh in its Explorer; the endpoint catches up with new tables in the background.

Lines and distinct orders differ by one because the till system sent order HG-40017 twice. Bronze keeps both copies on purpose. Now run the pipeline a second time and repeat the query. Because the table action is Overwrite, you should still see 60, not 120.

Common beginner mistakes

  • Leaving the table action on Append. Every rerun adds another full copy. After a week of daily runs your orders are counted seven times.
  • Typing columns in bronze. One bad value fails the whole copy at 06:00 when nobody is watching. Type in silver, not bronze.
  • Assuming Succeeded means correct. Succeeded means the copy finished. Only the row count tells you the data is all there.
  • Reaching for a pipeline when a Copy job would do. If you only need to copy, with no later steps, a Copy job is simpler. Pipelines earn their place when steps follow the copy, as in lesson 7.

On the brewhouse floor

Brewery A's packaging line writes a small CSV at the end of every shift: date, beer, package type and cases filled. Today someone emails it to the office. The same one-activity pipeline would pick it up from a folder and land it as a bronze table, untouched. When the night shift types "24x330" in the cases column, the copy still succeeds because bronze keeps text as text. The brewer can see exactly what was entered before anyone decides what it meant.
