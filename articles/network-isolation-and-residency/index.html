Network isolation and residency: private links, VNets and Multi-Geo

Three separate questions hide inside 'lock Fabric down': who can reach Fabric, what Fabric can reach and where the data sits. Each has its own tool, its own status on Microsoft Learn and its own list of things that quietly stop working.

11 Oct 2026 Fabric as of October 2026 Checked against Microsoft Learn Level 4 Ankur Napa SecurityGovernanceCapacity

Short answer

Split the request before you design anything.

  • Inbound: who can reach Fabric. Start with Microsoft Entra Conditional Access, which answers most "corporate network only" requests without private networking. For one sensitive workspace, use a workspace-level private link and deny public access to that workspace. Only when policy says nothing may be reachable from the internet, turn on tenant-level Private Link and then Block Public Internet Access.
  • Outbound: what Fabric can reach. Private endpoints protect traffic coming in, not going out. For firewalled sources use managed private endpoints (Spark), trusted workspace access (firewalled Azure Storage) or a virtual network data gateway. Then switch on workspace outbound access protection so nothing else leaves.
  • Residency: where the data lives. Each capacity sits in one Azure region and its workspaces' compute and OneLake data stay there. A capacity outside the tenant home region is Multi-Geo. Some metadata always stays in the home region, whatever you do.

Every switch in this list breaks something. Read the limitations before you flip it, not after.

Two interactions decide most designs. A workspace that restricts inbound access can no longer be reached through the tenant-level private link: it needs its own. And once a managed virtual network exists for a workspace, it cannot migrate to a capacity in a different region.

Reference design

Harbour Goods has its tenant home region in India, where the first person signed up. Most work is open behind Conditional Access. One finance workspace holds supplier payments and must not be reachable from the internet. A new European subsidiary must keep its order data in the EU.

Design notes:

  1. Payments workspace. Workspace-level private link with public access denied. Outbound access protection on, with one managed private endpoint to the ERP database and a data connection rule for the storage account the pipeline uses. The Fabric portal cannot set data connection rules while private links are on, so use the Outbound Gateway Rules REST API. It cannot join a deployment pipeline, so promote it with Git and scripts.
  2. Reporting for payments. Semantic models are not supported in a workspace with a workspace-level private link. Plan a separate reporting workspace and prove the connection path to the locked workspace in a test before promising it. Learn does not spell out every cross-workspace path.
  3. EU orders. A capacity in an EU region keeps compute and OneLake data for eu-orders-prod in that region. The permissions and report metadata still live in India. If the regulator's wording covers metadata, Multi-Geo alone does not meet it. Tell the client before the contract does.
  4. Region moves. When data moves region, the source copy can stay in the old region, inaccessible, for up to 30 days. Large storage format semantic models must not be moved at all. Deploy them fresh instead.

Questions to ask the client

  • Is the requirement "only from our network" or "no public endpoint exists"? The first is Conditional Access. The second is Private Link.
  • Which regulation, which data and what exact wording? Does it mention metadata, backups or support access?
  • Where is the tenant home region today? (Open the Help pane, select the About link and read the value next to Your data is stored in.)
  • Which sources sit behind firewalls? Are any on premises? Tenant Private Link stops the on-premises data gateway registering; the virtual network data gateway works.
  • Who uses Publish to web, email subscriptions, PDF export or Copilot today? Those users lose features under tenant Private Link.
  • Is any workspace that needs locking already in a deployment pipeline, or does it hold semantic models?
  • Will the sensitive workspaces run on trial capacity during the pilot? Workspace private links and outbound protection need an F SKU.
  • Will anyone share data with another tenant? Private Link and outbound protection both block that path.

Review checklist

  • The ask has been written down as inbound, outbound and residency, with one owner each.
  • Conditional Access is in place before any private networking work starts.
  • Every locked workspace is on an F SKU and is not in a deployment pipeline.
  • No semantic models were planned inside a workspace with a workspace-level private link.
  • Outbound access protection has an allow list: managed private endpoints or data connection rules for every real source.
  • Spark users know starter pools are gone in a managed virtual network and sessions start slower.
  • The Private Link limitations page was read end to end and every lost feature has a named user who accepted it.
  • New capacities were given 24 hours for private DNS before anyone expects private access.
  • Capacity regions are on an approved list and the home region limits are written into the residency statement.
  • Copilot and AI cross-geo tenant settings are off unless residency allows them.
  • The Workspaces - List Networking Communication Policies admin API is run on a schedule to audit which workspaces are locked.

Anti-patterns

  • Block Public Internet Access on a Friday afternoon. It takes 10 to 20 minutes to apply and turns off features nobody listed. Test on a separate tenant or start with one workspace.
  • Thinking a private endpoint secures outbound traffic. It only protects connections into Fabric. Outbound needs managed private endpoints, trusted workspace access, gateways and outbound access protection.
  • Locking the workspace that holds the reports. Semantic models are not supported there, so the lock cannot be turned on until they move out.
  • Promising residency with Multi-Geo alone. Tenant metadata stays in the home region. Some features, such as screenshots and data alerts, process data there too.
  • Moving a lakehouse workspace to another region. Workspaces with non-Power BI Fabric items cannot move region. Plan the region at creation.
  • Piloting on trial. Private links and outbound protection do not work on trial capacity, so the pilot proves nothing about production.

On the brewhouse floor

A distillery keeps a bonded warehouse ledger: every cask filled, moved and released, with the litres of pure alcohol on each line, which the excise officer can ask to see at any time. That ledger is the one workspace worth locking behind a workspace-level private link with outbound protection, reachable only from the site network. The production dashboards the stillhouse team checks on their phones stay open behind Conditional Access. One locked room, not a locked building, is usually what the regulator meant.
