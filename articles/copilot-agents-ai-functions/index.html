Copilot, data agents and AI functions: what each one does

Fabric has three AI features that sound alike and do different jobs. Copilot helps you build, a data agent answers questions over curated data and AI functions transform rows inside a pipeline. All three need a paid F2 or P1 and none of them run on a trial.

Short answer

Copilot is an assistant for the person building things: it writes DAX, SQL, KQL and notebook code and drafts report pages. A data agent is something you build once and hand to other people so they can ask questions of your data in plain English. AI functions are one-line calls to a language model inside a notebook, Dataflow Gen2 or T-SQL query that classify, summarise, translate or extract from text, row by row.

All three need a paid capacity, F2 or larger or a P SKU. The Fabric trial does not run Copilot, data agents or AI functions. If your capacity sits in an Indian region, an admin also has to switch on cross-geo processing first, because the models that power them run in the US and the EU Data Boundary.

Take Harbour Goods, a fictional retailer with an orders table and a few thousand free-text delivery notes from drivers. Copilot helps an analyst write the DAX for discount rate by region. A data agent lets a store manager in Pune ask "which stores missed their delivery window last week?" without opening a report. AI functions read every delivery note and tag it as damaged, late, wrong address or fine, so the notes become a column you can count.

A ten-minute tour

You need a workspace on a paid capacity to see all of this working. On a trial you can still look at the settings.

  1. Find the tenant switches. Open the admin portal and go to Tenant settings. Learn also describes the path as OneLake catalog > Govern > Configurations > Tenant settings, so your menu may read either way. Scroll to the Copilot and Azure OpenAI Service group.
  2. Read the main switch. Users can use Copilot and other features powered by Azure OpenAI is on by default for the whole tenant. Microsoft's own warning is that switching it on everywhere without planning raises capacity use, so many admins scope it to a security group.
  3. Read the two cross-geo settings. Data sent to Azure OpenAI can be processed outside your capacity's geographic region, compliance boundary, or national cloud instance is off by default. For a capacity in Central India or South India, Copilot stays off until this is on. Below it sits the matching stored outside setting, which data agents and notebook Copilot need because they keep conversation history.
  4. Check your capacity's region and size. In Capacity settings, note the SKU and region. Anything below F2 or on a trial will not show the AI features.
  5. Look for Copilot in an editor. Open a notebook, a Warehouse query or a Power BI report. The Copilot button sits in the ribbon. If it is greyed out, the message usually names the missing piece: capacity, tenant setting or region.
  6. Find the data agent item. In a workspace select + New item and search for Data agent. You add sources (lakehouse, warehouse, semantic model, KQL database, mirrored database or ontology), pick only the tables that matter and write instructions in plain English.
  7. See an AI function in the docs. In a Warehouse, SELECT AI_CLASSIFY('Box crushed at the door', 'damaged', 'late', 'wrong address', 'fine'); returns one label. The pandas and PySpark versions work the same way on a whole column. The T-SQL version is in preview.

What people get wrong

  • Running the AI demo on a trial. The trial page lists Copilot, data agents and AI functions as unsupported. The notebook Copilot page says trials are supported, which contradicts the overview and the Data Factory pages. Plan as if the trial runs none of them.
  • Thinking a Pro or PPU licence buys Copilot. It does not. Copilot follows the capacity, not the user. The exception is a Fabric Copilot capacity, an F2 or larger that admins can designate to carry Copilot billing for users in Pro or PPU workspaces. It does not cover AI functions.
  • Forgetting the region. An Indian capacity with the cross-geo setting off looks broken. It is not broken, it is switched off on purpose.
  • Pointing an agent at raw data. A data agent over a messy bronze table gives confident wrong answers. Ground it on a clean gold table or a semantic model with good names and descriptions.
  • Assuming AI is free once switched on. Copilot, agents and AI functions draw from the same capacity units as your reports and pipelines. AI functions default to gpt-5-mini at 8.40 CU seconds per 1,000 input tokens and 67.23 per 1,000 output tokens. On an F2, with 48 CU hours a day, a busy pilot can use a visible share of the day.
  • Treating answers as final. Copilot output is a draft. Data agents answer in English only and return at most 25 rows and 25 columns by default.

On the brewhouse floor

A brewery keeps a tasting log where the panel writes short notes on every batch, such as "slight buttery note" or "clean, a touch thin". AI functions can tag each note with the off-flavour it mentions, so a head brewer can count how often butteriness turns up by fermentation vessel instead of rereading a notebook of comments. A data agent over the clean batch table then lets the packaging lead ask which batches were held back last month and why. Copilot helps whoever builds the report write the measures. The panel still has to taste the beer: the model only counts what people wrote down.
