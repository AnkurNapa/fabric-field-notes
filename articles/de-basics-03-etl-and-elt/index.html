ETL and ELT: where Fabric does each

Lesson 3 of Data engineering basics. ETL cleans data before it lands; ELT lands it raw and cleans it inside the lakehouse. Learn which Fabric tool does which and build a small ELT view on Harbour Goods orders.

Ankur Napa 11 Oct 2026, 5 min read

Short answer

ETL means extract, transform, load: take data from the source, clean it on the way, then store only the cleaned result. ELT means extract, load, transform: copy the data in exactly as it arrived, then clean it inside your own storage. Fabric supports both. Dataflow Gen2 is the natural ETL tool. A pipeline or Copy job that lands raw data, followed by a notebook or SQL, is ELT. Most modern lakehouse work leans towards ELT, because keeping the raw copy lets you fix mistakes later.

Why it matters for your career

Interviewers use ETL versus ELT to check whether you understand why data is stored the way it is. Your answer also tells them whether you would protect the raw data when a cleaning rule turns out to be wrong.

The idea

Three words first:

  • Extract: read data out of the source system.
  • Transform: change it. Fix types, remove duplicates, add calculated columns.
  • Load: write it into your storage.

The only difference between ETL and ELT is the order of the last two steps.

ETLELT
OrderExtract, transform, loadExtract, load, transform
What gets storedOnly the cleaned dataThe raw data, then cleaned tables beside it
If a rule was wrongGo back to the source and extract again, if it still has the dataRe-run the transform on the raw copy you kept
Fabric toolsDataflow Gen2, light mapping in a Copy activityCopy job or pipeline to land, then notebook, SQL or Dataflow Gen2 to transform
SuitsSmall, well understood sources, business users who know Power QueryMost lakehouse work, changing rules, audit needs

Take one Harbour Goods line: HG-40017 was sent twice by the till system. With ETL a cleaning step drops the copy before anything is stored. Nobody can later prove the till sent it twice. With ELT both copies land, the clean table shows one and the raw table still holds the evidence. When finance asks why the till export and the report disagree by one line, ELT gives you the answer.

Fabric's own guidance points the same way: land raw data first, typically with a Copy job, then refine it. Dataflow Gen2 is still excellent when the person doing the work thinks in Power Query, the same tool as in Excel and Power BI.

Try it in Fabric

You will do the transform half of ELT with plain SQL. The raw data is already loaded: it is the orders_try table from lesson 2, which should hold 60 rows after the overwrite.

  1. Open lh_harbour and switch to the SQL analytics endpoint using the dropdown at the top right of the ribbon.
  2. Select New SQL query and run this to create a view, a saved query that behaves like a table but stores nothing:
CREATE VIEW dbo.v_order_lines AS
SELECT
    order_id,
    TRY_CAST(order_date AS date)            AS order_date,
    store_id,
    product_id,
    TRY_CAST(quantity AS int)               AS quantity,
    CAST(TRY_CAST(quantity AS int)
         * TRY_CAST(unit_price AS decimal(10,2))
         * (1 - TRY_CAST(discount AS decimal(4,2)))
         AS decimal(12,2))                  AS net_amount
FROM dbo.orders_try;
  1. Refresh the Explorer. The view appears under Views.
  2. Run the check:
SELECT COUNT(*) AS order_lines, SUM(net_amount) AS net_revenue_inr
FROM dbo.v_order_lines;

You should see 60 order lines and 156269.85 INR. TRY_CAST tries to convert a value and returns NULL instead of failing when it cannot, so the impossible date 2026-09-31 on order HG-40059 does not stop the query.

That figure is not yet the true revenue. It still counts the duplicated order, a quantity of -2 and an order from a store that does not exist. Lesson 6 finds them and lesson 8 removes them. That is ELT working as intended: the raw table never changed, so you can keep improving the rules.

The SQL analytics endpoint is read only for data: you can create views here but not update rows. When you need to write cleaned tables, use a notebook, a pipeline or Dataflow Gen2. If your team prefers T-SQL, use a Warehouse.

Common beginner mistakes

  • Cleaning in the copy step and throwing away the raw file. It feels tidy. It removes your only evidence when a rule is wrong.
  • Thinking ELT means never cleaning. ELT still transforms. It does it after landing.
  • Using CAST on messy data. One bad value fails the whole query. Use TRY_CAST, then count the NULLs it produced.
  • Choosing a tool by fashion. Pick by who maintains it. A Power Query expert will keep a dataflow healthy; a notebook nobody can read will rot.

On the brewhouse floor

At Distillery A each still run is logged with the stillman's cut points: the moment the spirit stream switched from heads to hearts and from hearts to tails. An ETL design might store only the hearts volume. An ELT design keeps every raw reading from the run, then calculates the hearts figure. When the head distiller later moves the cut point by half a percent of alcohol, the ELT version can recalculate a year of runs. The ETL version can only start counting from today.
