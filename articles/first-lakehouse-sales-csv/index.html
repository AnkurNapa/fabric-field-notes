Your first lakehouse: land sales data and query it

Create a workspace and a lakehouse, upload an orders CSV, turn it into a Delta table and query it with T-SQL from the SQL analytics endpoint. No code beyond one query.

Ankur Napa 11 Oct 2026, 8 min read

Short answer

A lakehouse is a folder in OneLake with two areas: Files for anything raw and Tables for Delta tables that every Fabric engine can read. You upload a CSV to Files, use Load to tables to write it out as Delta, then switch to the SQL analytics endpoint and query it with T-SQL. The whole thing takes about fifteen minutes on a trial capacity. The endpoint is read only, which is the first thing that surprises people and the right default for a first build.

What you will build

One workspace, one lakehouse called lh_sales, one Delta table called orders and one T-SQL query that answers a question a regional manager would actually ask: how much did each store sell this quarter and how hard did it lean on discounts to get there?

The data is a synthetic quarter of orders for Harbour Goods, a fictional retailer with six stores across India. It holds 60 orders placed between July and September 2026. Each row has the order, the store, the product, the quantity, the unit price in rupees, the discount as a fraction (0.05 is five per cent) and the net amount, worked out as quantity times unit price times one minus the discount. Download it here: first-lakehouse-sales-csv.csv.

I picked an orders export on purpose. In most mid-size retailers this file still starts life as a nightly download from the till system, gets emailed to someone in finance and ends up in a spreadsheet named something like Q3_sales_FINAL_v3. Landing it in a lakehouse is the smallest useful step from that inbox to something the whole team can query.

Before you start

  • Capacity. The workspace needs a Fabric capacity: an F SKU, a P SKU with Fabric enabled or a Fabric trial. A Power BI Pro or Premium Per User licence alone does not give you a capacity, so it cannot host a lakehouse.
  • Licence. A free Fabric licence is enough to create a lakehouse in a workspace that sits on an F or trial capacity.
  • Role. Contributor or higher on the workspace. You will be Admin if you create it yourself.
  • Tenant settings. A Fabric administrator must have Users can create Fabric items switched on. To start a trial yourself, Users can try Microsoft Fabric paid features must also be on. If New item shows no Lakehouse card, one of these is the reason.

Steps

1. Create the workspace

  1. In the Fabric portal select Workspaces > + New workspace.
  2. Name it harbour-dev.
  3. Expand Advanced and under Workspace type pick Fabric Trial or Fabric with your capacity.
  4. Select Apply.

2. Create the lakehouse

  1. In the workspace select + New item, search for Lakehouse and select it.
  2. Name it lh_sales. Lakehouse names start with a letter and may contain only letters, digits and underscores, up to 123 characters.
  3. Leave Lakehouse schemas ticked. It is the default and later features such as materialised lake views need it.
  4. Select Create. The lakehouse opens in the Explorer pane with Tables and Files.

Fabric also creates a SQL analytics endpoint with the same name. You do not set it up; it appears beside the lakehouse in the workspace list.

3. Upload the CSV to Files

  1. Download the sample CSV.
  2. In the lakehouse ribbon select Get data > Upload files. You can also use the ... next to Files and pick Upload > Upload files.
  3. Choose the file and select Upload, then close the pane.
  4. Select Files in the Explorer. The CSV is there, untouched.

Files is the raw shelf. Nothing in it is queryable through the SQL analytics endpoint and Fabric does not try to discover tables in it.

4. Load it to a Delta table

  1. Hover over the CSV in Files, select ... > Load to tables > New table.
  2. In Load file to new table set Schema to dbo.
  3. Set New table name to orders. Lowercase letters, digits and underscores only, no dashes or spaces, up to 256 characters.
  4. Leave Column header ticked and Separator as a comma.
  5. Select Load.

When it finishes, expand Tables > dbo > orders and select it to preview the rows. The CSV in Files is still there. You now have two copies on purpose: the file as it arrived and the table as Delta.

Load to tables does not let you set column names or types. It infers them. That is fine for a first table and the reason the next article moves to a notebook.

5. Open the SQL analytics endpoint

  1. In the lakehouse ribbon, top right, open the dropdown that says Lakehouse and switch to SQL analytics endpoint.
  2. Select New SQL query.

If orders is not in the endpoint's Explorer yet, select the Refresh button in the Explorer toolbar. Metadata sync runs in the background after every Delta commit and on a busy workspace it can lag by a minute or two.

6. Ask the manager's question

Paste this and select Run:

SELECT
    store_id,
    COUNT(*)                                              AS orders,
    SUM(CAST(quantity AS int))                            AS units,
    SUM(CAST(net_amount AS decimal(12,2)))                AS net_sales,
    CAST(AVG(CAST(discount AS decimal(4,2))) * 100 AS decimal(5,2)) AS avg_discount_pct
FROM dbo.orders
GROUP BY store_id
ORDER BY net_sales DESC;

The casts are belt and braces. If Load to tables inferred numbers they cost nothing; if it inferred text they stop the query failing.

Check it worked

Run a row count and a self-check on the money. The second part recomputes the net amount from quantity, price and discount and reports the worst difference against the stored value:

SELECT
    COUNT(*)                                       AS orders,
    SUM(CAST(quantity AS int))                     AS units,
    SUM(CAST(net_amount AS decimal(12,2)))         AS net_sales,
    MAX(ABS(CAST(quantity AS int)
            * CAST(unit_price AS decimal(10,2))
            * (1 - CAST(discount AS decimal(4,2)))
            - CAST(net_amount AS decimal(12,2))))  AS worst_net_gap
FROM dbo.orders;

Expected: orders 60, units 202, net_sales 307519.85 and worst_net_gap 0.00. Every price here is in whole rupees and every discount is a multiple of five per cent, so there is no rounding to forgive.

Where this breaks

  • The endpoint is read only. INSERT, UPDATE and DELETE fail on lakehouse tables through the SQL analytics endpoint. You can create views, functions and procedures there, but data changes go through Spark, a pipeline or Dataflow Gen2. If your team needs T-SQL writes, that is a Warehouse. The choice is about who writes, not what the data looks like.
  • The table is there but the endpoint cannot see it. Metadata sync is asynchronous. Use Refresh in the endpoint. In a pipeline, call the Refresh SQL analytics endpoint metadata REST API before the next step instead of a fixed wait. Large numbers of lakehouses in one workspace make the lag worse.
  • Tables written outside the Tables area. Delta written under Files never appears in the endpoint. Nor do external tables created from Spark code. Only Delta under /Tables is discovered.
  • Bad names. Spaces or dashes in a file name upset Load to tables and dashes are not allowed in table names. Rename Q3 sales - FINAL.csv to something like orders.csv before loading.
  • Sharing a lakehouse is not sharing the data. Someone given only Read on the item can see it but cannot query it from SSMS. Share with Read all with SQL analytics endpoint for T-SQL access and add Read all with Apache Spark only for people who need notebooks.

On the brewhouse floor

A small brewery has the same problem with a different sheet: the brew log. Each batch gets a row on a clipboard by the brewhouse with the date, the beer style, the fermenter (FV-03, say) and the volume in hectolitres. Upload that typed-up sheet to Files at Brewery A, load it to a brew_log table and the query above becomes hectolitres brewed per style this quarter. The clipboard stays on the wall. The numbers stop living in one person's spreadsheet.
