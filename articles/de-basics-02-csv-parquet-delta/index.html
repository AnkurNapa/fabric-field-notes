Data engineering basics, lesson 2 of 8

Files, tables and formats: CSV, Parquet and Delta

Lesson 2 of Data engineering basics. CSV is for exchanging data, Parquet is for reading it fast and Delta adds a change log on top of Parquet. Load a Harbour Goods orders file and look inside the Delta table it becomes.

11 Oct 2026 Fabric as of October 2026 Checked against Microsoft Learn Ankur Napa Lakehouse

Short answer

A CSV file is plain text with one row per line and commas between the values. Every tool can read it, which is why systems export it. A Parquet file stores data column by column in a compressed binary form, so analytics tools read it much faster. Delta is a table format made of Parquet files plus a folder of small log files that records every change. Fabric stores every table as Delta, so the usual journey is CSV in, Delta out.

Why it matters for your career

Format questions come up in almost every data engineering interview because the wrong format causes slow reports, broken loads and lost history. Knowing why Fabric chose Delta also explains features you will use daily, such as undoing a bad load.

The idea

Here are the first three lines of the Harbour Goods orders file you will use all course:

order_id,order_date,store_id,product_id,quantity,unit_price,discount
HG-40001,2026-07-02,ST-014,P-101,4,699,0.05
HG-40002,2026-07-02,ST-011,P-106,2,899,0.05

The first line is the header: the column names. Every other line is one order. That is all a CSV is. It has no data types, so 699 is just three characters until something decides it is a number.

FormatHow it stores dataGood atWeak at
CSVText, row by rowExchange between systems, opening in ExcelSpeed, data types, large volumes
ParquetBinary, column by column, compressedFast reads of a few columns from many rowsEditing single rows, human reading
DeltaParquet files plus a _delta_log folderReliable updates, history, undoBeing opened outside data tools

Column by column matters because a question like "total quantity by store" needs only two of the seven columns. A row-based CSV makes the reader scan everything. Parquet lets it skip the five columns it does not need.

The Delta log is the clever part. Each time the table changes, Fabric writes a new numbered log file saying which Parquet files were added or removed. Readers follow the log, so they never see a half-finished load. Because old versions stay in the log for a while, you can also look at the table as it was before a mistake. That is called time travel.

Try it in Fabric

Use the lh_harbour lakehouse from lesson 1. Download the sample: harbour-goods-orders.csv. It has 60 order lines and is 2,744 bytes.

  1. Open lh_harbour. In the Explorer, select ... next to Files and create a subfolder called landing. The menu label may read New subfolder or New folder.
  2. Select ... next to landing > Upload > Upload files, choose the CSV and select Upload.
  3. Select the landing folder. The file appears in the main view and you can preview it as a table.
  4. Hover over the file, select ... > Load to tables > New table. Set the schema to dbo and the table name to orders_try. Leave Column header ticked and the separator as a comma. Select Load.
  5. Expand Tables > dbo and select orders_try. The main view shows rows. Use the dropdown above the grid to switch from Table view to File view.
  6. In File view you will see one or more .parquet files and a _delta_log folder. Open _delta_log. It holds one file ending in 00000000000000000000.json: version 0 of the table.
  7. Go back to the CSV in Files and run Load to tables again, this time choosing Existing table, orders_try and Append.
  8. Check _delta_log again. A second file ending in ...0001.json has appeared.

Now switch the lakehouse to its SQL analytics endpoint (the dropdown at the top right of the ribbon), select New SQL query and run:

SELECT COUNT(*) AS order_lines FROM dbo.orders_try;

You should see 120, because you loaded the same 60 lines twice. Run Load to tables once more with Existing table and Overwrite, refresh the endpoint Explorer and run the count again. You should see 60 and a third log file. The table changed three times; the log remembers all three.

Common beginner mistakes

  • Expecting Parquet to be smaller on a tiny file. At 60 rows the Parquet file can be as big as the CSV. The savings show at millions of rows.
  • Appending the same file twice. Append adds rows; it does not check for duplicates. You just proved that with 120 rows.
  • Editing files inside a Delta folder by hand. Delete a Parquet file from File view and the log still points to it. The table breaks. Change tables through Fabric tools only.
  • Trusting inferred types. Load to tables guesses the column types and you cannot set them there. A notebook gives you control, which lesson 8 uses.

On the brewhouse floor

At Winery A the cellar team logs lab results for each tank: free sulphur dioxide in milligrams per litre, measured before bottling. Someone re-keys tank T-12 from 28 to 18 by mistake and the overwrite goes through. In a CSV the old value is gone. In a Delta table the earlier version is still in the log, so the winemaker can see what the number was, when it changed and put it back. For a sulphur figure that decides whether wine is safe to bottle, that history is worth the format choice on its own.
