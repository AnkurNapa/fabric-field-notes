Dashboarding basics, lesson 1 of 8

What a dashboard is for (and what it is not)

A dashboard answers a few questions that the same people ask on a schedule, fast enough that they stop asking you. This lesson sets up the Harbour Goods sales model in Fabric that the rest of the course builds on.

11 Oct 2026 Fabric as of October 2026 Checked against Microsoft Learn Ankur Napa Power BIDirect Lake

Short answer

A dashboard is a page that answers a small number of recurring questions for a named group of people. "How did we sell last week, where and at what margin?" asked every Monday by the regional managers is a dashboard. "Can you pull me everything for every store?" is not. That is a data export. A dashboard that tries to be both ends up being neither.

In Power BI two words cause confusion on day one. A report is one or more pages of visuals built on one semantic model, with filters and slicers. A Power BI dashboard is a single page of tiles pinned from reports, with no slicing at all. In everyday speech people call both "the dashboard". This course builds reports, because that is what most teams open each morning. It uses "dashboard" in the everyday sense.

Why it matters for your career

Anyone can drag a chart onto a page. The person who asks "who opens this, when and what do they decide afterwards?" before building anything is the one who gets trusted with the next project. That question is most of the job.

The idea

Before you build, write one sentence: who looks, how often, to decide what. Then list the questions the page must answer. Anything that does not serve one of them goes somewhere else.

For Harbour Goods, a retailer with six stores in four regions, the sentence is: "Regional managers look on Monday morning to decide where to push stock and whether to cut discounts." That gives three questions:

Try it in Fabric

This sets up the model every later lesson uses. You need a workspace on a Fabric capacity or a Fabric trial and the Contributor role or higher on it. Download the three sample files (synthetic, July to September 2026): dash-basics-orders.csv (96 orders), dash-basics-products.csv (six products) and dash-basics-stores.csv (six stores).

  1. In the workspace select + New item > Lakehouse and name it lh_harbour. A lakehouse is storage in Fabric that holds files and tables.
  2. In the Explorer, select ... next to Files > Upload > Upload files and upload the three CSVs.
  3. For each file select ... > Load to tables > New table. Name the tables orders, products and stores. Table names allow lowercase letters, digits and underscores only, so type the name rather than accepting one built from the file name.
  4. On the lakehouse ribbon select New semantic model (some tenants label it New Power BI semantic model). Name it sm_harbour_sales, tick the three tables and select Confirm. A semantic model is the layer that holds relationships and calculations. Created this way it is a Direct Lake model, which reads the tables in place instead of copying them.
  5. The model opens in the browser. If it is read only, switch to Editing in the top right. Drag orders[product_id] onto products[product_id] and set Many to one, cross filter Single. Do the same for orders[store_id] onto stores[store_id].
  6. Select File > Create new report. On the blank page insert a text box (the label may read Text box under Insert) and type your one-sentence purpose. Save the report as rpt_harbour_sales.

Check it worked: drop a Table visual on the page with orders[order_id] in it. The visual should list 96 rows. Delete the visual afterwards; the purpose sentence stays.

Common beginner mistakes

  • Starting with the visuals. Opening the canvas before writing the purpose sentence produces a page of everything, which answers nothing.
  • Building for everyone. Finance, store managers and the board ask different questions. One page per audience beats one page that pleases none.
  • Treating the dashboard as the data source. If people export every visual to Excel, they needed a table or a dataset, not a dashboard. Ask what they do with the export.
  • Skipping the relationships. Without them, a chart of net sales by region shows the same total on every bar.

On the brewhouse floor

At Brewery A the head brewer walks the cellar at seven every morning and asks the same three things: which tanks are ready to package, which ferments are stalling and is anything running warm. That is the purpose sentence, already written by habit. A dashboard for the cellar answers those three questions for FV-01 to FV-08 and nothing else. The monthly cost per hectolitre belongs on a different page for a different person.
