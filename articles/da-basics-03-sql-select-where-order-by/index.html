Data analysis basics, lesson 3 of 8

SQL basics on the SQL analytics endpoint

Lesson 3 of Data analysis basics. SELECT picks columns, WHERE picks rows and ORDER BY sorts them. Write your first queries against the Harbour Goods orders table in Fabric and check every answer.

11 Oct 2026 Fabric as of October 2026 Checked against Microsoft Learn Ankur Napa Lakehouse

Short answer

SQL is the language for asking questions of tables. Three parts do most of the work: SELECT says which columns you want, WHERE says which rows to keep and ORDER BY says how to sort the result. In Fabric you write SQL in the SQL analytics endpoint of a lakehouse. It is read only, so nothing you type in this lesson can damage the data.

Why it matters for your career

SQL is in nearly every analyst job advert. It has been for thirty years. Once you can read and filter a table yourself, you stop waiting for someone else to export a spreadsheet for you.

The idea

A query reads like a sentence. Think of it as "show me these columns, from this table, for rows like this, in this order".

SELECT order_id, order_date, product_id, quantity   -- which columns
FROM dbo.orders                                      -- which table
WHERE store_id = 'ST-011'                            -- which rows
ORDER BY order_date;                                 -- what order

dbo is the schema, a named folder that holds tables. Text values go in single quotes, numbers do not. Anything after -- is a comment that SQL ignores.

WHERE can combine conditions with AND (both must be true) and OR (either can be true). Comparisons use =, <> (not equal), <, >, <= and >=. ORDER BY sorts ascending by default; add DESC for largest first. TOP 10 after SELECT limits the result to ten rows, which is handy while you explore.

Try it in Fabric

Use the lh_harbour lakehouse from lesson 1.

  1. Open lh_harbour and switch the ribbon dropdown, top right, from Lakehouse to SQL analytics endpoint.
  2. Select New SQL query. A query editor opens. You can run one statement by selecting it and choosing Run.
  3. Look first. Run SELECT TOP 10 * FROM dbo.orders;. The star means every column. Use it to explore, not in finished work.
  4. Count the rows: SELECT COUNT(*) AS order_lines FROM dbo.orders;
  5. Run the store query from The idea above.
  6. Now a two-condition filter. Which order lines had three or more units of a product priced over 1,000 INR?
SELECT order_id, order_date, store_id, product_id, quantity, unit_price
FROM dbo.orders
WHERE quantity >= 3
  AND unit_price > 1000
ORDER BY unit_price DESC, order_date;

If a table does not appear in the endpoint's Explorer, select Refresh. The endpoint picks up new tables in the background and can lag a minute behind the lakehouse.

Common beginner mistakes

  • Double quotes around text. In T-SQL, Microsoft's dialect of SQL, 'ST-011' is a value and "ST-011" is treated as a column name, so the query fails.
  • Forgetting that blanks are special. The empty quantity in HG-40056 is a NULL, meaning "no value". WHERE quantity = NULL finds nothing; write WHERE quantity IS NULL.
  • Mixing AND and OR without brackets. WHERE a OR b AND c means a OR (b AND c). Add brackets so the next reader does not have to guess.
  • Trying to fix data here. UPDATE and DELETE fail on the SQL analytics endpoint because it is read only. That is a feature. Lesson 6 shows how to clean data without changing the source.

On the brewhouse floor

A distillery keeps a cask register: one row per cask with its warehouse, fill date, strength and bulk litres. The same three clauses answer the daily questions. WHERE warehouse = 'W2' AND fill_date < '2023-01-01' finds casks old enough to sample. ORDER BY strength_abv DESC puts the hottest first. A cask with an empty strength is a NULL. It is usually the one that was refilled and never re-dipped.
