Data analysis basics, lesson 1 of 8

What a data analyst actually does

Lesson 1 of Data analysis basics. A data analyst turns a business question into a trustworthy answer and explains it to the person who asked. You will set up the lakehouse and the three Harbour Goods tables the whole course uses.

11 Oct 2026 Fabric as of October 2026 Checked against Microsoft Learn Ankur Napa Lakehouse

Short answer

A data analyst takes a question from someone in the business, finds the data that can answer it, checks that data can be trusted, works out the answer and explains it in plain words. Most of the job is not charts. It is asking what the question really means, finding out why two numbers disagree and saying "I don't know yet" when the data is not good enough. In this course you do all of it in Microsoft Fabric, Microsoft's data platform, on one small set of shop data.

Why it matters for your career

Analyst roles are the most common way into a data career because they need curiosity and care more than years of programming. If you can write a clear query, spot a bad number and explain the answer to a manager, you are already doing the work. Every later role, from analytics engineer to data scientist, builds on these habits.

The idea

Harbour Goods is a fictional retailer with stores in six Indian cities. It sells everyday goods such as water bottles, towels and desk lamps. Three tables describe its business. A table is data laid out in rows and columns, like a spreadsheet tab with strict rules.

TableOne row isColumns
ordersone line on a till receiptorder_id, order_date, store_id, product_id, quantity, unit_price, discount
productsone thing the shop sellsproduct_id, name, category, unit_cost
storesone shopstore_id, city, region, opened

A typical week for an analyst at Harbour Goods looks like this:

  1. A question arrives. "Is the Pune store doing well?" It is vague, so the first job is to sharpen it. That is lesson 2.
  2. Find and read the data. The orders table has what we need. Querying it with SQL is lessons 3 to 5.
  3. Check it. Are there duplicate rows? Missing values? A date that cannot exist? Lesson 6.
  4. Summarise it honestly. An average can mislead. Lesson 7 covers the statistics that matter.
  5. Explore and share. A notebook for digging, a Power BI report for the manager. Lesson 8.

A few words you will meet all course. Fabric is the platform. A workspace is a shared folder in Fabric where a team keeps its items. A lakehouse is an item that stores files and tables together. The SQL analytics endpoint is the part of a lakehouse that lets you ask questions in SQL, the standard language for querying tables.

Try it in Fabric

This sets up everything the course needs. You need a workspace on a Fabric capacity or a Fabric trial and the Contributor role or higher on it. If you already built lh_harbour in the data engineering course, reuse it and skip to step 4.

  1. Download the three sample files (synthetic data, July to September 2026): harbour-goods-orders.csv, harbour-goods-products.csv and harbour-goods-stores.csv.
  2. In the Fabric portal select Workspaces > + New workspace, name it harbour-dev and select Apply. Under Advanced pick a Fabric or trial capacity if asked.
  3. In the workspace select + New item, search for Lakehouse and select it. Name it lh_harbour, leave Lakehouse schemas ticked and select Create.
  4. In the lakehouse, hover over Files, select ... > Upload > Upload files, choose all three CSVs and select Upload.
  5. Hover over harbour-goods-orders.csv, select ... > Load to tables > New table. Set the schema to dbo and the table name to orders. Leave Column header ticked and select Load. Table names allow only lowercase letters, digits and underscores.
  6. Repeat for the other two files, naming the tables products and stores.
  7. Expand Tables > dbo and select each table to preview it.

Check it worked. You should see three tables. orders has 60 rows, products has 9 and stores has 6. Fabric guessed each column's type when it loaded the file, so do not worry yet if a date column shows as text. Lesson 6 explains why that happens here.

Common beginner mistakes

  • Starting with the chart. The chart comes last. A wrong number in a beautiful chart is still wrong, only more convincing.
  • Trusting the first total. This sample has a few deliberate problems, like real data. You will find them over the next five lessons.
  • Loading a file twice. If you choose Existing table and Append by mistake, every row is doubled. Drop the table and load it again as a new table.
  • Thinking you must know Python first. SQL gets you a long way. The notebook in lesson 8 is a bonus, not an entry ticket.

On the brewhouse floor

At Brewery A the question is rarely "how are sales?" It is "why did we lose 40 cases on the bottling line last Tuesday?" The analyst does the same five steps: sharpen the question, find the packaging log, check it, summarise it and explain it. The check matters most, because a line counter that missed a reset makes a good shift look like a disaster. Same lakehouse, same SQL, different table.
