Data engineering

C25 Question

How do we use pandas or Polars in Fabric without blowing memory?

Checked 11 Oct 2026 Ankur Napa

The answer

Use the Python notebook (no Spark): it starts in about 5 seconds on a 2 vCore, 16 GB single node by default, scalable to 64 vCores, with Python 3.10, 3.11 or 3.12 kernels (3.12 default, 3.10 out of support October 2026) and DuckDB, Polars and delta-rs preinstalled. Microsoft's benchmark guidance: Python engines win below about 140 MB compressed and keep an edge to about 1 to 2 GB, Spark with the Native Execution Engine becomes competitive around 10 to 13 GB and is fastest from about 100 GB. Learn's decision rule is Python below about 1 GB compressed, Spark from 1 GB or with growth. A single-node 8 vCore starter pool Spark session also starts in about 5 seconds, so Python is not automatically cheaper. Prefer DuckDB, Polars or PyArrow over pandas for anything large; push filters down instead of loading whole tables.

Decision rule

Use a Python notebook with Polars or DuckDB below about 1 GB compressed; switch to Spark at 1 GB or when data is growing quickly.

Watch out

No Python engine can write deletion vectors (default on in Runtime 2.0), so writing to Spark-created tables fails; delta-rs supports only VACUUM LITE and no engine has auto compaction, so tables they write need explicit delta-rs maintenance. DuckDB INSERT never writes checkpoints. Unverified: `toPandas()` in a Spark notebook pulls everything to the driver and is the usual out-of-memory cause (I01 lists it as a driver OOM cause).
