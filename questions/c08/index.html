Data engineering

C08 Question

How do we build data quality checks into the pipeline?

Checked 11 Oct 2026 Ankur Napa

The answer

The native option is materialized lake views: declare CONSTRAINT ... CHECK (...) ON MISMATCH DROP | FAIL in the view, with FAIL as the default; dropped row counts show in lineage and a built-in data quality report. In notebooks, write explicit checks (row counts, nulls, key uniqueness, referential checks) and fail the run with a raised error that the pipeline catches. Microsoft's Well-Architected guidance also lists Great Expectations for data validation and pytest or nutter for notebook logic.

How

CREATE MATERIALIZED LAKE VIEW silver.orders (
  CONSTRAINT valid_amount CHECK (amount > 0) ON MISMATCH DROP
) AS SELECT * FROM bronze.orders

Decision rule

Use MLV constraints for row-level rules on Spark SQL transforms; use notebook or test-framework checks for set-level rules such as reconciliation totals.

Watch out

If a view has both DROP and FAIL constraints, FAIL wins. The data quality report uses DirectQuery and is capped at 1 million returned rows per query.
